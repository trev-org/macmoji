# macmoji: prototype plan (draft for Trevor to approve)

Status: research + plan only. No repo created, no code pushed. The target repo is `trev-org/macmoji`.
Uncertain items are marked **[UNVERIFIED]**.

## 1. What it does
A menu-bar-only (LSUIElement) macOS app. When you type `:` plus 2 or more shortcode characters `[a-z0-9_+-]`, a small picker opens near the caret. Arrow keys move the selection, Enter/Tab insert, Esc cancels. Inserting removes `:query` and puts the emoji in its place. Typing the closing colon (`:fire:`) auto-replaces an exact match.

## 4. Key technical choices
### Keystroke capture
- An `NSEvent` global monitor is observe-only: it can't swallow keys, and it needs Accessibility. A `CGEventTap` with `.listenOnly` needs only Input Monitoring (ListenEvent). To **swallow** arrows/Enter/Tab/Esc while the picker is open we need `.defaultTap`, which needs **Accessibility**. Posting synthetic events is also Accessibility (PostEvent). (Quinn @ Apple: https://developer.apple.com/forums/thread/707680, https://developer.apple.com/forums/thread/735204; WWDC19 quote in https://github.com/aahung/Unshaky/issues/157)
- So the plan is one `.defaultTap` and the **Accessibility** grant. Input Monitoring may not be needed on top of it (one report says an AX-trusted process can create listen taps: https://github.com/antonynjoro/ZeroG/blob/main/docs/macos-permissions-gotchas.md) **[UNVERIFIED on current macOS; test in M1]**.
- Gotchas: a non-nil tap is not proof of permission. Handle `tapDisabledByTimeout` / `tapDisabledByUserInput` by re-enabling the tap. Keep the callback well under ~1s or macOS disables the tap. Re-signing changes the TCC identity, so permissions must be re-granted (https://danielraffel.me/til/2026/02/19/cgevent-taps-and-code-signing-the-silent-disable-race/).
- **Secure input:** when a password field has secure input on, event taps stop receiving the keystrokes (Apple TN2150). Also check `IsSecureEventInputEnabled()` (Carbon), and check whether the focused AX role/subrole is `AXSecureTextField`; if so, stay idle. Note that some apps (e.g. 1Password, Terminal's "Secure Keyboard Entry") leave secure input on globally **[behavior per app UNVERIFIED]**.
- **Letting ':' pass through:** the tap never swallows `:` or letters, only navigation keys while the picker is visible. It arms only if the char before `:` is start-of-text, whitespace, or `(`/`[`, read via AX or the state machine's last key. It shows the picker only after 2 or more `[a-z0-9_+-]` chars. It cancels on space, a second `:` with no match, a digit straight after `:` (so `10:30` is safe), `/` (so `http://` is safe), mouse click, app switch, or focus change. `time: 10:30` never opens: there's a space after the colon.

### Caret position (fallback chain)
1. `AXFocusedUIElement` → `kAXSelectedTextRangeAttribute` → `AXUIElementCopyParameterizedAttributeValue(kAXBoundsForRangeParameterizedAttribute)` with range (loc-1, 1) if length 0. Reliable in native AppKit/Cocoa text views; Safari/WebKit generally works **[UNVERIFIED per site]**.
2. Chrome/Electron (Slack, VS Code, Cursor, Notion): the AX tree is lazy. Set `AXManualAccessibility=true` on the app element (Electron: https://electronjs.org/docs/latest/tutorial/accessibility). Chrome uses `AXEnhancedUserInterface`, which breaks window-manager animations (https://bugzilla.mozilla.org/show_bug.cgi?id=1664992). This must be reapplied per PID, and Electron 28+ may need it on the renderer element (https://github.com/FuJacob/tabby/issues/19, community report). VS Code/Cursor's Monaco editor exposes a hidden textarea, so bounds may be wrong or zero **[UNVERIFIED]**.
3. Sanity-check the rect: non-zero, and inside the focused element's frame (`kAXPositionAttribute`/`kAXSizeAttribute`). If it fails, use the bottom-left of the focused element.
4. Last resort: the mouse location. Convert AX coordinates (top-left origin) to Cocoa (bottom-left), handle multiple screens.

### Insertion
- Delete `len(":query")` with synthetic Backspace events (CGEvent keyDown/up for kVK_Delete), then insert.
- **A: `CGEvent.keyboardSetUnicodeString`** (default). No clipboard is touched and it works in most apps. Gotchas: long strings get chunked (~20 UTF-16 units per event), ZWJ/skin-tone sequences can split in some apps **[UNVERIFIED]**, and terminals or remote desktops may mangle it.
- **B: pasteboard + Cmd+V.** Reliable for multi-codepoint emoji. You must save and restore every pasteboard item/type with a delay (~150–300 ms), and it races with clipboard managers. Expandly and FujiMoji use it as a fallback.
- **C: AX `kAXSelectedTextAttribute` set.** Atomic in native fields (it could replace the shortcode range in one step), but it often silently fails in web/Electron apps and bypasses undo grouping in some apps.
- Plan: A by default, a per-app "paste mode" list (B) for terminals, browsers and any app that misbehaves. C is experimental. Post events with a short spacing (~1–5 ms); suppress our own events with an event-source userData tag so the tap ignores them.

### Popup UI
An `NSPanel` subclass with `[.nonactivatingPanel, .borderless]`, `level = .popUpMenu`, `canBecomeKey = false`, `hidesOnDeactivate = false`, hosting SwiftUI via `NSHostingView`. The target app keeps focus. Keyboard navigation is done in the **event tap**: while visible, return `nil` for ↑ ↓ ⏎ ⇥ ⎋ and drive the view model; all other keys pass through and update the query. Mouse clicks on rows work without activation.

### Emoji data
- **emojibase-data** (MIT; https://github.com/milesj/emojibase/blob/master/LICENSE). Shortcode presets: `iamcal` (aliased `slack`; comes from Cal Henderson's emoji-data; no skin-tone codes, may lag the newest Unicode), `github`, `emojibase`, `cldr` (https://emojibase.dev/docs/shortcodes/). Slack has no official list, so iamcal is the best approximation.
- Alternatives: github/gemoji (MIT, GitHub-style names), iamcal/emoji-data directly (MIT **[license UNVERIFIED this session]**).
- Plan: iamcal names first, then github and emojibase aliases merged. Apply skin tone via emojibase `skins` for the chosen default tone (Slack's `::skin-tone-2` style as an optional suffix).
- Search: exact shortcode > prefix > substring > subsequence fuzzy > keyword. Match tier is
  always compared before frecency; within a tier use `log2(count + 1) × 0.5^(age / 7 days)`,
  persisted as capped JSON in Application Support, then matched-name length. ~2k entries, so a
  linear scan is fine.

### Custom Slack emoji
`emoji.list` needs the `emoji:read` scope with a bot or user token (https://docs.slack.dev/reference/methods/emoji.list, https://docs.slack.dev/reference/scopes/emoji.read.md). The response maps name→image URL or `alias:`. Outside Slack, an image only works in rich-text editors that accept pasted images (Mail, Notes, Google Docs); it fails in plain text fields. Inside Slack, Slack's own picker already handles them. **Recommendation: not in v1.** Possible v2: insert `:name:` text when the frontmost app is Slack, or paste an image in rich-text apps.

### Packaging
- Can't be sandboxed or ship on the Mac App Store with this design: a modifying event tap plus synthetic input, AX control of other apps, and `AXManualAccessibility` writes all need the non-sandboxed Accessibility privilege. (Listen-only taps can run in the sandbox per Quinn, but swallowing keys and inserting text need Accessibility, and that's incompatible with the sandbox and App Store review in practice **[policy detail UNVERIFIED]**.)
- Personal use: sign with a stable identity (an Apple Development cert, or Developer ID if he has a paid account) so TCC grants survive rebuilds. Ad-hoc signing changes the identity on every build, so grants have to be redone. Notarization only matters for distributing to others.
- `SMAppService.mainApp.register()` for launch at login (macOS 13+).
- Minimum: **macOS 14** (recommended; current SwiftUI/MenuBarExtra polish). 13 is possible.
- Project: Xcode project (or XcodeGen/Tuist) for the .app bundle, Info.plist and signing. Core logic in a local Swift package for fast `swift test`. `swift run` makes TCC attribute permissions to Terminal, so always test the bundled app.

### CI
GitHub-hosted macOS runners (https://github.com/actions/runner-images/blob/main/images/macos/macos-15-Readme.md) can `xcodebuild build` and run `swift test` for MacmojiCore. TCC on runners is pre-configured for some tools (configure-tccdb script). Granting a custom app Accessibility means editing the user TCC.db, which is fragile (https://github.com/actions/runner-images/discussions/8961). Plan: CI = build + unit tests only. Permission-dependent behavior gets a manual test checklist, plus an optional local "harness" test app.

## 5. Milestones
- **M1: smallest working prototype (1–2 days).** Menu bar app plus an Accessibility onboarding prompt. `.defaultTap` keyDown, the trigger state machine with the pass-through rules, a bundled ~1.8k emoji JSON (iamcal names), prefix and fuzzy search, a non-activating panel at the AX caret (falling back to the element frame, then the mouse), arrows/Enter/Tab/Esc swallowing, backspace + unicode-string insertion, and a hard skip in secure fields. Target apps: TextEdit, Notes, Safari, Chrome (basic). Unit tests for the state machine and search.
- **M2: hardening.** Tap auto-re-enable and health check, self-event tagging, the per-app blocklist (Slack and Discord on by default), the paste-mode fallback with clipboard restore, Electron/Chrome AX wake per PID, multi-monitor coordinates, IME/composition skip (`kAXMarkedTextRange` / non-Latin layouts), non-US keyboard layouts (detect `:` via the produced character, not the keycode).
- **M3: polish.** Frecency, skin-tone setting, `:name:` exact auto-replace, Settings window, SMAppService launch at login, pause toggle, signing with a stable identity.
- **M4 (optional).** Custom snippets, Slack custom emoji, Sparkle updates, notarized DMG.

## 6. Risks and per-app notes
| App | Caret | Insert | Notes |
|---|---|---|---|
| TextEdit/Notes/Mail | good | unicode OK | baseline |
| Safari | mostly good **[UNVERIFIED]** | unicode OK | contenteditable can vary |
| Chrome/Arc/Edge | needs AX wake | unicode, maybe paste | AXEnhancedUserInterface side effects |
| Slack (Electron) | needs AX wake | — | **block by default**: it has its own `:` picker |
| VS Code/Cursor | probably poor (Monaco) **[UNVERIFIED]** | unicode OK | VS Code has its own suggest widget; use the mouse/element fallback |
| Notion | variable **[UNVERIFIED]** | paste may be safer | Notion has its own `:` emoji picker; consider blocking |
| Terminal/iTerm2 | element frame only | paste mode | Secure Keyboard Entry stops all capture |
| Password fields | — | — | always skip |
Other risks: the tap timing out under load, TCC grants lost after re-signing, key-ordering races (the user keeps typing during insertion), and conflicts with other text expanders.
